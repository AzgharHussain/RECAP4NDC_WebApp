FMPS — Forest Monitoring and Patrolling System

FMPS (Forest Monitoring and Patrolling System) is a mobile and web application developed for the Gujarat Forest Department to monitor forest areas, track patrolling activities, detect NDVI (Normalized Difference Vegetation Index) changes, and report forest incidents.

This Privacy Policy describes how the data collected through the FMPS application is handled. By using the FMPS application, you consent to the practices described in this policy.

2. Information We Collect

2.1 Account & User Information

  • Username and User ID — assigned by the Forest Department for authentication.
  • Password — stored as a securely hashed value; plain-text passwords are never stored.
  • Role / Designation — e.g., Forest Guard, Range Forest Officer, Divisional Forest Officer.
  • Government Department affiliation — Division, Range, Beat, Round information.

2.2 Location & Patrol Data

  • GPS track data — start and end coordinates, route path (geometry), and total distance travelled during each patrol.
  • Start and end timestamps of each patrolling session.
  • Patrol metadata — officer name, division, range, beat, round, patrolling type, number of staff, patrolling location (inside/outside forest).
  • Current location — district and village when patrolling outside forest areas.

2.3 Images

  • Patrol images — photographs captured during patrolling, with optional notes.
  • Incident images — photographs of forest incidents (fire, encroachment, illegal felling, wildlife sighting, etc.) with category and severity classification.
  • NDVI change images — satellite-derived imagery showing vegetation change detected at specific pixel locations.

2.4 NDVI / Satellite Data

  • NDVI change records — pixel ID, NDVI change value, longitude, latitude, status, village, division, range, beat, and round for each detected change.
  • Coupe / plantation boundary data — geographic boundaries uploaded as shapefiles or KML files.

2.5 Incident Reports

  • Incident category and sub-category — e.g., Forest Fire, Encroachment, Illegal Felling, Wildlife.
  • Incident severity — Low, Medium, High, Critical.
  • Incident location — GPS coordinates, division, range, beat.
  • Incident description and images.

2.6 Push Notification Data

  • Firebase Cloud Messaging (FCM) token — used to send push notifications about NDVI changes and alerts.
  • Notification preferences — user-selected tables, ranges, and areas of interest.
  • Notification log — record of notifications sent, delivery status, and timestamps.

2.7 Device & Technical Information

  • IP address — logged for audit and security purposes.
  • User-Agent string — browser or app version information.
  • Device location — GPS coordinates submitted by the mobile app when reporting incidents or patrols.

2.8 Audit Logs

  • Login/logout events, password changes, record creation/update/deletion, file uploads, boundary management, and notification subscription changes.
  • Audit logs are retained for a period of 2 years for system events and 37 days for transactional logs, in accordance with the data retention policy.

3. How We Use the Information

  • To authenticate users and manage access control based on roles.
  • To record and monitor forest patrolling activities and ensure coverage of designated areas.
  • To detect and respond to NDVI changes indicating potential deforestation or vegetation loss.
  • To report, classify, and track forest incidents for timely response.
  • To send push notifications to forest officers about detected changes and alerts.
  • To generate reports and analytics for forest management decision-making.
  • To maintain audit trails for accountability and security.

4. Data Storage & Security

  • PostgreSQL database — stores patrol records, NDVI change data, incident reports, user accounts, and boundary metadata. Hosted on secure government cloud infrastructure (SDC).
  • MongoDB — stores patrol and incident images (as base64-encoded data), image metadata, and notification logs.
  • GeoServer — serves geospatial boundary layers for visualization on the web dashboard.
  • Encryption — all communication between the mobile app, web dashboard, and backend APIs uses HTTPS/TLS encryption.
  • Authentication — JWT (JSON Web Token) based authentication with token expiration. Passwords are hashed using bcrypt.
  • Access control — role-based access control (RBAC) ensures users can only access data relevant to their designation and jurisdiction.
  • Input validation & sanitization — all user inputs are validated and sanitized to prevent SQL injection, XSS, and other attacks.
  • Rate limiting — API endpoints are protected by rate limiting to prevent abuse.

5. Data Sharing & Disclosure

  • Data collected through FMPS is not sold or shared with any third party for commercial purposes.
  • Data is accessible only to authorized Gujarat Forest Department personnel based on their role and jurisdiction.
  • Aggregate, anonymized data may be used for government reporting, research, and policy planning.
  • Data may be disclosed to law enforcement or government authorities if required by law.

6. Data Retention

  • Patrol records, incident reports, and NDVI change data — retained indefinitely as government records, unless otherwise directed by the Forest Department.
  • Audit logs — system event logs retained for 2 years; transactional logs retained for 37 days.
  • Notification logs — retained for operational reference and audit purposes.
  • Images — retained as long as the associated patrol or incident record exists.

7. User Rights

  • Access — Users can view their own patrol records, incident reports, and profile information through the app.
  • Correction — Users can update incident notes and image notes. Profile changes are managed by department administrators.
  • Notification control — Users can subscribe to or unsubscribe from NDVI change notifications at any time.
  • Account deactivation — Managed by the Forest Department administration. Users should contact their supervising officer or the department email to request account changes.

8. Children's Privacy

FMPS is a government departmental application used by authorized forest department personnel only. It is not directed at children and does not knowingly collect data from children.

9. Third-Party Services

  • Firebase Cloud Messaging (Google) — used for push notifications. Firebase may process the FCM token and notification delivery data subject to Google's Privacy Policy.
  • GeoServer (Open Source) — hosted on the department's own infrastructure for serving geospatial data.
  • Leaflet / OpenStreetMap tiles — used for map visualization in the web dashboard. Map tile requests may be processed by the tile provider.
